## Why

The widget is published on the Mendix Marketplace as component 245825 and currently shows up in Studio Pro's toolbox as
"Check box / radio selector" — a name that describes two controls rather than the job the widget does. Following the
product decision (WC-3223), it is renamed to **Option Selector**: one name that covers both control types and reads as a
single input element. The rename must not disturb any existing app, so the widget's identity — its ID, package name, and
CSS contract — stays exactly as it is, and the toolbox description must keep the words "checkbox" and "radio button" so
developers searching for either term still find it.

## What Changes

- Studio Pro toolbox name becomes `Option Selector` (`<name>` in `CheckboxRadioSelection.xml`).
- The currently **empty** `<description />` is filled in with text that names the widget and explicitly mentions
  checkbox and radio button, preserving search discoverability in the toolbox and Marketplace.
- Marketplace listing title (`marketplace.appName`) and the npm `description` field become "Option Selector"-based.
  The listing is updated in place under the existing `appNumber` 245825 — release automation reads `appName` for the
  Marketplace draft and the release-PR title.
- Remaining user-visible copy is retitled: the read-only style property description, the three editor dropzone
  placeholders, the design-time empty-caption fallbacks, and `README.md`.
- `CHANGELOG.md` gains a `[Unreleased] → Changed` entry announcing the new name.
- **No** behavior, props, API, styling, or dependency change. **Not breaking**: the widget ID
  `com.mendix.widget.web.checkboxradioselection.CheckboxRadioSelection`, the `widgetName`
  `CheckboxRadioSelection`, the mpk name, the npm package `@mendix/checkbox-radio-selection-web`, the folder name, the
  generated typings, and the `widget-checkbox-radio-selection*` CSS classes are all deliberately left untouched, so
  existing pages and custom styling keep working after an upgrade.
- Docs-site page in the `mendix/docs` repo is **out of scope** for this change; `<helpUrl>` keeps pointing at
  `/appstore/widgets/checkboxradioselection`, so the URL slug stays valid whenever that page lands.

## Impact

- **Widget config**: `src/CheckboxRadioSelection.xml` (`<name>`, `<description>`, `readOnlyStyle` description).
- **Packaging / release**: `package.json` (`description`, `marketplace.appName`). No version bump — release automation
  owns versions. `automation/utils` consumes `appName` for the Marketplace draft and release-PR title; no automation
  change needed.
- **Editor / design time**: `src/CheckboxRadioSelection.editorConfig.ts`, `src/helpers/utils.ts`,
  `src/helpers/Preview/PreviewCaptionsProvider.tsx`.
- **Docs in-repo**: `README.md`, `CHANGELOG.md`.
- **Generated artifacts**: `dist/locales/en-US/com.mendix.widget.web.checkboxradioselection.checkboxradioselection.json`
  is regenerated by the `prebuild` step; its filename derives from the widget ID, so it is unchanged.
  `typings/CheckboxRadioSelectionProps.d.ts` regenerates identically.
- **Untouched by design**: `src/package.xml`, all `CheckboxRadioSelection.*` filenames, SCSS class names,
  `e2e/SelectionControls.spec.js` locators and `/p/checkboxradioselection` page URL (owned by the external
  `mendix/testProjects` branch), no `packages/modules/*` bundles this widget.
- **Runtime code**: none. **Dependencies**: none.
